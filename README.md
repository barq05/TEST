# AURABOT — الموقع + لوحة التحكم

مشروع static (HTML/CSS/JS من غير build) بيشتغل على **GitHub Pages**، وبيتصل بـ **Firebase** (Authentication بـ Google + Firestore).
الموقع والداشبورد بيستخدموا **نفس مشروع Firebase ونفس الـ database**.

- الموقع: `https://barq05.github.io/aurabot/`
- لوحة التحكم: `https://barq05.github.io/aurabot/admin/`

---

## 1) هيكل الملفات

```
aurabot/
├── index.html              ← الموقع (الرئيسية، المتجر، التذاكر، من نحن، طلباتي)
├── admin/
│   └── index.html          ← لوحة التحكم
├── firebase-config.js      ← ⭐ الملف الوحيد اللي بتعدّل فيه (قيم Firebase)
├── assets/                 ← اللوجوهات
├── firebase/
│   ├── firestore.rules     ← قواعد الأمان (تتنسخ في Firebase Console)
│   └── firestore.indexes.json  ← Index اختياري (لحساب إجمالي المبيعات)
├── .nojekyll
└── README.md
```

> ملاحظة: ملفات `firebase/` مش بتتشغّل على GitHub Pages، دي بتتنسخ يدويًا في Firebase Console (خطوة 3).

## 2) القيم اللي لازم تضيفها (في `firebase-config.js` بس)

افتح `firebase-config.js` وبدّل الجُمل العربية بالقيم الحقيقية:

| الحقل | مطلوب؟ | تلاقيه فين |
|---|---|---|
| `apiKey` | ✅ | Firebase Console ← ⚙️ Project settings ← General ← Your apps ← Config |
| `authDomain` | ✅ | نفس المكان (شكله `اسم-المشروع.firebaseapp.com`) |
| `projectId` | ✅ | نفس المكان |
| `storageBucket` | ✅ | نفس المكان |
| `messagingSenderId` | ✅ | نفس المكان |
| `appId` | ✅ | نفس المكان |
| `discordInvite` | اختياري | رابط دعوة سيرفرك `https://discord.gg/xxxx` (لو فاضي الزرار بيتحوّل لفتح تذكرة) |

- القيم دي **مش سرّية** (بتظهر لأي زائر في أي موقع Firebase)؛ الحماية الحقيقية في Rules.
- ❌ **ممنوع** تحط Service Account أو Private Key في أي ملف في المشروع. المشروع مش محتاجهم أصلًا.
- لو سبت القيم الافتراضية، الموقع هيعرض شاشة «محتاج تضيف إعدادات Firebase».

## 3) إعداد Firebase (لو لسه ما خلصتش)

1. **Authentication** ← Sign-in method ← فعّل **Google**.
2. **Authentication ← Settings ← Authorized domains** ← تأكد إن `barq05.github.io` موجود (من غيره الدخول هيفشل بـ `auth/unauthorized-domain`).
3. **Firestore Database** ← Create database (Production mode).
4. **Firestore ← Rules**: امسح كل اللي موجود، والصق محتوى `firebase/firestore.rules` كامل، واضغط **Publish**.
5. (اختياري لكن مفضّل) **Firestore ← Indexes ← Composite ← Add index**: Collection `orders`، الحقل `status` (Ascending) و `total` (Ascending)، Query scope: Collection. ده بيخلي «إجمالي المبيعات» يتحسب من السيرفر. من غيره الداشبورد بيحسبه من آخر 500 طلب.
6. لو بتستخدم Firebase CLI: `firebase deploy --only firestore:rules,firestore:indexes`.

**المالك الرئيسي** ثابت جوّه الكود والـ Rules: `barqelhadidy@gmail.com`. مش محتاج تضيفه في أي collection. أي حد تاني لازم يتضاف من صفحة «الفريق» عشان يدخل الداشبورد.

## 4) النشر على GitHub Pages

1. اعمل Repository باسم **`aurabot`** على حساب `barq05` (لازم الاسم يطابق الرابط).
2. فك الـ ZIP وارفع **محتويات** مجلد `aurabot` (مش المجلد نفسه) لجذر الـ repo، بحيث `index.html` و `admin/` يبقوا في الجذر. بالأمر:
   ```bash
   git init
   git add .
   git commit -m "AURABOT initial"
   git branch -M main
   git remote add origin https://github.com/barq05/aurabot.git
   git push -u origin main
   ```
   أو من الموقع: Add file ← Upload files (اسحب كل الملفات والمجلدات).
3. من الـ repo: **Settings ← Pages ← Build and deployment**: Source = *Deploy from a branch*، Branch = `main`، Folder = `/ (root)` ← Save.
4. استنى دقيقة أو اتنين ويفتح `https://barq05.github.io/aurabot/`.

> الـ repo هيبقى public ومعاه `firebase-config.js` — ده عادي ومقصود (قيم عامة). متحطش أي أسرار.

## 5) أول تشغيل: اختبار بالترتيب

1. افتح `/aurabot/admin/` وسجّل دخول بـ `barqelhadidy@gmail.com` ← لازم تشوف كل الأقسام.
2. **طرق الدفع**: أضف طريقة (مثلًا فودافون كاش + الرقم + التعليمات).
3. **المنتجات**: أضف منتج (واحد منهم علّم «الأكثر شراءً»).
4. **أكواد الخصم**: أضف كود تجريبي.
5. **الفريق**: أضف Gmail تاني بدور «مستقبل طلبات» وجرّب تدخل بيه (متصفح تاني/Incognito) ← لازم يشوف نظرة عامة + طلبات + تذاكر بس.
6. جرّب بحساب Gmail مش مضاف ← لازم تظهر «غير مصرّح لك».
7. افتح الموقع من متصفح تاني، سجّل دخول، اطلب منتج (جرّب الكود) ← الطلب يظهر في الداشبورد فورًا.
8. غيّر حالة الطلب، واتبادل رسائل من دردشة الطلب. بعد أول طلب تظهر «طلباتي» للعميل.
9. افتح تذكرة من الموقع ورد عليها من الداشبورد.

## 7) افتراضات محتاجة تأكيدك (لأن المواصفات ما حدّدتهاش)

- كل أعضاء الفريق يقدروا يغيّروا حالة الطلبات ويردّوا على التذاكر.
- حذف الطلبات والتذاكر: المالك الرئيسي فقط.
- **طرق الدفع قراءتها عامة** (أي زائر يشوفها) لأن العميل لازم يشوف رقم الدفع؛ الكتابة للمالك الرئيسي فقط.
- تعديل دور عضو وإزالته: المالك الرئيسي فقط (الأدمن والأونر يضيفوا بس).
- معدل التحويل = عدد الطلبات ÷ عدد الزيارات الفريدة (زائر/يوم) في آخر 30 يوم.
- إجمالي المبيعات = مجموع الطلبات بحالة «تم الدفع» أو «تم التسليم».
- إجابتين من الأسئلة الشائعة (FAQ) في الموقع من صياغتي؛ راجعهم.
- الأدوار المخصصة: ترتيب 1–3 وصلاحيات من الأقسام المتاحة، مع الحد الأدنى للترتيب لبعض الأقسام.
- تفاصيل صلاحيات كل دور (الـ workflow) هتبعتها لاحقًا، وأي تعديل بيحصل في موضعين: `BUILTIN` في `admin/index.html` ودالة `builtinPerms()` في `firestore.rules`.

## 8) تنبيهات صريحة

- **الكود والـ Rules اتفحصوا بصيغة وتشغيل تجريبي ببيئة Firebase وهمية، لكن مش ضد مشروعك الحقيقي** (مفيش اتصال بالشبكة عندي). نفّذ قائمة الاختبار في الخطوة 5 قبل الإطلاق للعملاء، وراقب تبويب **Rules ← Rules Playground** لو حاجة اتمنعت بالغلط.
- صفحة «طلباتي» بتتخفي من الواجهة لو معندكش طلبات، لكن الحماية الحقيقية للبيانات في Rules (كل عميل يقرأ طلباته هو بس)، لأن الموقع static ومينفعش يخفي صفحة على مستوى السيرفر.
- أي خطأ `permission-denied` في الداشبورد معناه إن الـ Rules مش منشورة بنسختها الأخيرة أو إن صلاحية الدور مش كافية.
- مشاكل شائعة: `auth/unauthorized-domain` (ضيف الدومين في Authorized domains)، `auth/popup-blocked` (اسمح بالـ popups)، شاشة إعداد Firebase (القيم لسه عربي في `firebase-config.js`).
